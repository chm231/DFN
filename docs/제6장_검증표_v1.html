제6장 검증표 — v1 파이프라인 재생성 결과 (2026-08-03)

목적. 보고서 제6장의 검증표 수치는 v0 파이프라인(3점법 방향 · window_mc $k_r$ · unit-MC $P_{32}$ 보정)으로 산출된 값이다. 본문 방법론을 v1(외부 3D 방향 · hybrid $k_r$ · 해석식 $P_{32}$ 보정)으로 수정할 경우 표의 수치도 함께 갱신되어야 하므로, 동일 벤치마크 입력에 v1 파이프라인을 적용해 재생성한 결과를 정리한다.

동일 조건. DFN 참값(dfn_export_for_python.h5, 균열 18,483,834개)과 거친 막장면 mesh를 v0 실행과 동일 파일로 고정하고, 방법(추정기)만 v1으로 교체했다. 따라서 아래 차이는 전부 방법 변경에 기인한다. 대상: Laxemar 벤치마크, 막장면 4매(x = 0/1/2/3 m), 절리군 1·2·3·5 (Set 4는 지수분포이므로 멱법칙 역산 대상에서 제외, 정책 D002).

재현 명령은 문서 말미 §5에 수록.

평균 pole 각오차는 4.1° → 4.8°로 소폭 증가했는데, 이는 방향 정보의 품질 저하가 아니라 표본 구성의 변화 때문이다. v0는 3점법이 성공한 절리선(전체의 54–76%)만으로 평균을 냈고, v1은 관측된 모든 절리선을 사용한다. 막장면과 만나는 절리 표본 자체가 면에 수직인 절리를 과대표집하는 구조적 편향(교차확률 편향)을 갖고 있어, 표본을 늘린다고 평균 pole이 참값에 더 가까워지지는 않는다. 각오차는 전 절리군 8.9° 이하로 v0와 같은 수준을 유지하며, 방향 품질의 실질 지표인 κ가 개선된 것이 방법 교체의 성과다.

2.1 ⚠ 이 표를 그대로 "성능 저하"로 읽어서는 안 되는 이유

v0의 1.6%는 실제로 달성 가능한 정확도가 아니다. v0는 절리군마다 $\ell_{min}$(우도 적합에 쓰는 최소 절리선 길이)을 다르게 선택했는데(표 V-2의 0.50/0.30/0.75/0.30), 이 선택이 참값 $k_r$에 가장 가까운 후보를 고르는 방식으로 이루어져 있었다. 즉 정답을 보고 하이퍼파라미터를 고른 결과이며, 참값을 모르는 실제 현장에서는 재현할 수 없는 수치다(정책 D013 위반 — 2026-07-30 발견, 커밋 c696703에서 수정).

v1은 $\ell_{min}$을 전 절리군 공통 0.5 m로 고정하고 선택 절차에서 참값을 완전히 배제했다. 표 V-2의 두 열은 같은 조건의 비교가 아니라, "정답을 본 추정"과 "정답을 보지 않은 추정"의 비교다. 참값을 배제한 동일 조건에서 두 방법을 20개 시드로 비교한 재판정 결과는 다음과 같으며, hybrid(v1)가 3승 1무로 우세하다.

2.2 본 시드의 위치

표 V-2는 단일 시드의 결과이므로 위 RMSE 대역과 대조해 읽어야 한다. 절대오차는 Set 1 0.15, Set 2 0.21, Set 3 0.49, Set 5 0.30으로, Set 1·2·5는 해당 절리군의 RMSE 이내이고 Set 3만 RMSE(0.244)의 두 배로 벗어난 불리한 추출이다. Set 3이 유일하게 95% CI에 참값을 담지 못한 것도 같은 이유다.

Set 3의 계통 편향에는 v1의 알려진 한계도 함께 작용한다 — 모델은 절리선을 터널 단면 다각형으로 자르는데 관측 절리선은 요철 mesh의 footprint로 잘려 있어 기준이 어긋나며(mesh 면적이 다각형 대비 −3.85%), 기준을 일치시킨 실험에서는 전 절리군 $k_r$ 오차가 0.04 이하로 회수되었다. 차기 버전 개선 항목이다(통합본 §4.7).

2.3 보고서 반영 시 권고

표 V-2를 그대로 싣는 경우 v0 열은 삭제하거나 각주로 내리고, v1 열만 본표로 제시할 것을 권한다. 두 열을 나란히 두면 "방법을 바꿔 정확도가 나빠졌다"는 오해를 부르는데, 실제로는 v0 수치가 검증 기준을 위반해 산출된 값이기 때문이다. 대신 §2.1의 20시드 blind RMSE 표를 방법 비교 근거로 싣는 것이 정확하다.

해석. $P_{32}$는 두 방법이 실질적으로 동등하다. 보정계수 $C$는 v1(해석식)이 v0(unit-MC) 대비 일관되게 1.9–5.0% 작으며, 이는 unit-MC의 $C$가 면적 기준 불일치로 +2~4% 과대 추정된다는 기존 규명(통합본 제3부 §2.5)과 부호·크기가 모두 일치한다. $C$가 작아진 만큼 $\widehat{P_{32}} = P_{21}^{obs}/C$는 커지며, 참조값 대비 과소추정이던 Set 2·3은 개선되고 이미 과대추정이던 Set 1·5는 오차가 소폭 늘었다. 방법의 우열이 아니라 계통 편향 제거의 결과가 절리군별 부호에 따라 다르게 나타난 것이다.

Set 2의 −25.7%는 두 방법 공통이며 방법 문제가 아니다 — 관측 절리선이 46개로 가장 희소하고(다음으로 적은 Set 3의 1/3), 평균 pole이 터널축과 이루는 각이 작아 교차확률이 낮은($C = 0.31$로 최소) 절리군이라 관측 $P_{21}$ 자체의 표본 변동이 크다.

3.1 ⚠ 미해결 사항 — v1의 $P_{32}$ 신뢰구간

v1의 해석식 보정은 결정론적 구적이라 $C$에 표집 불확실성이 없고, $C$는 $k_r$과도 무관하다. 그 결과 현재 구현은 $\widehat{P_{32}}$의 상·하한이 점추정값과 동일한 퇴화(degenerate) 구간을 출력한다(표에서 CI 열을 뺀 이유).

다만 v0의 CI도 통계적 신뢰구간은 아니었다 — MC 복제 간 산포(즉 시뮬레이션 잡음)일 뿐이며, 실제로 Set 2에서는 v0 CI [0.735, 0.750]이 점추정값 0.726을 포함하지 못하는 모순도 있었다. 따라서 두 버전 모두 $P_{32}$의 참된 불확실성을 제시하지 못하고 있다.

보고서에 CI를 실으려면 관측 $P_{21}$의 표본 변동(막장면 수·절리선 수 유한성)을 전파하는 별도 절차가 필요하다. 본 표에서는 CI 열을 생략하고 점추정만 제시할 것을 권한다.

5. 재현 명령

작업 디렉터리는 handoffv1/(v1 패키지가 dfn_analysis로 로드되도록), 경로는 리포 루트 기준.

# 1) 절리선 재추출 (외부 3D 방향)
python -m dfn_analysis.export_setwise_3d_traces \
  --input   <ROOT>/storage/output/pipeline_test_laxemar/dfn_export_for_python.h5 \
  --rough-mesh-h5 <ROOT>/storage/output/pipeline_test_laxemar/rough_face_mesh/rough_face_mesh_collection.h5 \
  --outdir  <ROOT>/storage/output/pipeline_v1_laxemar/trace_dataset \
  --trace-normal-source external

# 2) kr (hybrid 기본, lmin 0.5 고정, 참값 미사용 선택)
python -m dfn_analysis.estimate_kr \
  --trace-h5 <ROOT>/storage/output/pipeline_v1_laxemar/trace_dataset/trace_dataset_3d.h5 \
  --site laxemar --target-set 1 2 3 5 \
  --kr-true-map 1:2.85 2:3.04 3:3.01 5:3.60 \
  --run-bootstrap --n-bootstrap 100 \
  --outdir <ROOT>/storage/output/pipeline_v1_laxemar/kr

# 3) P32 (해석식 보정)
python -m dfn_analysis.estimate_p32_mc_calibrated \
  --trace-h5 <ROOT>/storage/output/pipeline_v1_laxemar/trace_dataset/trace_dataset_3d.h5 \
  --dfn-h5   <ROOT>/storage/output/pipeline_test_laxemar/dfn_export_for_python.h5 \
  --rough-mesh-h5 <ROOT>/storage/output/pipeline_test_laxemar/rough_face_mesh/rough_face_mesh_collection.h5 \
  --site laxemar --target-set 1 2 3 5 \
  --kr-summary-csv <ROOT>/storage/output/pipeline_v1_laxemar/kr/kr_summary_by_set.csv \
  --bootstrap-csv  <ROOT>/storage/output/benchmark1_parsimonious/inputs/final_kr_bootstrap_summary_effective_rmin.csv \
  --calibration-factor-mode analytic_esinphi \
  --outcsv <ROOT>/storage/output/pipeline_v1_laxemar/p32/p32_summary.csv

# 4) 참값 대조표 (리포 루트에서 실행)
python scripts/compare_pipeline_to_laxemar.py --base storage/output/pipeline_v1_laxemar

--kr-true-map은 CSV의 검증 열을 채우기 위한 것으로, 추정 자체에는 사용되지 않는다(D013). 출력: storage/output/pipeline_v1_laxemar/comparison_vs_laxemar.csv

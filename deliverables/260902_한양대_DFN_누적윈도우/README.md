# 누적 막장면 윈도우 조건부 DFN — 블록 안정성 검토용 (2026-09-02)

막장면 07(x ≈ 12.6~12.8 m)까지의 실측 데이터를 **누적 윈도우 4가지**(면 1–7 / 2–7 /
3–7 / 4–7)로 나눠 각각 역산하고, 윈도우별 random seed 5개(101/202/303/404/505)로
전방 도메인 DFN을 생성한 것입니다. 총 20개 JSON.

- 폴더: `f01-07/` `f02-07/` `f03-07/` `f04-07/` (각 5개 파일, 파일명 끝 `_seed<번호>`)
- 도메인: 각 윈도우 마지막 면(07) 전방 10 m × 터널 단면 + halo 5 m.
  네 윈도우 모두 **같은 예측 구간(x ≈ 12.7 ~ 22.7 m)**을 서로 다른 데이터 양으로
  예측하는 구성입니다. (터널축을 윈도우별로 재적합하므로 x 값이 소수점 수준에서
  다릅니다 — 파일명·meta 참조)

## 절리군 번호 통일 (2026-09-02 적용)

**모든 JSON의 set_id는 f01-07 기준으로 통일되어 있습니다** — 윈도우가 달라도 같은
번호는 같은 방향군입니다. 기준 방향(f01-07, trend/plunge/κ):

| 통일 set | trend | plunge | κ |
|---|---|---|---|
| 1 | 325.8° | 7.4° | 9.6 |
| 2 | 190.3° | 36.7° | 12.7 |
| 3 | 27.0° | 38.1° | 13.5 |

통일 시 병합 이력 (평균 pole 축성 각거리 30° 이내만 병합):

- f02-07: 1→1, 2→2, 3→3 (변경 없음, 각 3~5° 일치)
- f03-07: 원래 set 4(막장면 인접 소군, 기준 set 3과 11°)를 **set 3에 병합**
- f04-07: 원래 set 2(기준 set 3과 16°)를 **set 3에 병합** — 따라서
  **f04-07에는 통일 set 2가 없습니다** (4개 면만으로는 set 2 방향군이 독립
  클러스터로 분해되지 않음; 해당 절리들은 다른 군에 흡수되었거나 소수군으로 제외됨)

병합된 군의 원래 kr/P32 등은 각 JSON의 `meta.set_parameters_original`에 보존되어
있고, 매핑은 `meta.set_unification`에 기록되어 있습니다. 병합 후
`meta.set_parameters`의 P32는 성분 합입니다. 위 "윈도우별 역산 요약" 표의 절리군
번호는 **원래(병합 전) 번호** 기준입니다.

## JSON 스키마 (표 6-4 형식)

- `fractures[]`: `center_xyz_m`, `normal_xyz`(단위 법선), `radius_m`, `set_id`,
  `label` ("observed" = 절리선 복원 / "unobserved" = 확률 생성)
- `tunnel_wall_traces[]`, `meta`(좌표계, 도메인, 터널 단면 폴리곤, 파라미터, seed)
- 좌표계: x = 굴진 방향, y = North, z = Up, 단위 m

## 사용 시 유의

1. **면 07은 매핑 품질 이상 면입니다** (절리선 79개 vs 정상 면 550~860개, 관측면적은
   최대). 07의 면적이 관측면적 분모에 포함되므로 **P21/P32가 다소 하향 편향**될 수
   있으며, 면 수가 적은 윈도우일수록(f04-07) 영향 비중이 큽니다.
2. 시드 5개는 동일 통계·다른 실현입니다. observed 균열은 윈도우 내에서 시드 간
   동일하고 unobserved만 달라집니다. 블록 결과는 시드 5개의 평균/범위로 평가 권장.
3. 생성 조건: rmax 25 m, 생성 rmin 0.5 m, 검출한계(lmin) 0.5 m, 부재 조건화 적용
   (관측 막장면에 0.5 m 이상 절리선을 남길 확률 균열 제거).
4. 예측 구간(x ≈ 12.7~22.7 m)에는 실측 면 08~12가 존재하므로, 블록 검토 결과를
   실측 절리선과 대조하는 블라인드 검증이 가능합니다.

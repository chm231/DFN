## 배경

- 샘플링 자체는 이미 직접 N 생성(`compute_num_fractures_from_P32` + 역CDF). 기각 없음.

  → 터널 바로 옆에서 실제 관측된 절리가 한 장도 없는 20장으로 블록해석을 해 온 셈.

## 변경
`dfn_analysis/reconstruct_discs_from_traces.py:337-362` 후보간선 이중 루프를 교체.
판정식은 불변, '누구를 언제 검사하느냐'만 변경:
- **블록 분할**: 절리선은 이산 막장면 위에만 있으므로 (set, 면 p, 면 q) 블록으로 나눠

  `sqrt` → 제곱거리 비교, `acos` → 코사인 비교(`|cos| >= cos(angle_deg)`).
- 간선 라벨은 `i < j` 로 정규화(공면거리는 a,b 교환에 불변).
- 비적응 경로(`adaptive_sep=False`)는 게이트가 `max_sep_m` 상수라 면 블록 분할 없이
  set 분할 + 벡터화만 적용.
- 병합 루프(`_UF`, `_fit_plane_svd`, `_same_face_one_chord`)는 미변경.
- `_axial_angle_deg` 는 geometric association 경로(line 216)에서 계속 사용되므로 존치.

# (3) kr 역산 최적화 — 해석식 bin 질량 벡터화 + h5 일괄 로드

## 정정: kr 역산의 최종 방안은 window_mc 가 아니라 **hybrid** 다
`estimate_kr.py:263` — `--likelihood-mode {window_mc, hybrid}`, **default="hybrid"**.
파일 헤더: hybrid = 참 현길이 분포를 닫힌형(해석식)으로, 창·절단 변환은 kr불변 MC 커널
1회로 분해. 종전 §4.6 의 "window_mc 우위" 판정은 lmin 선택에 참값을 쓴 **오라클 평가**였고,
§4.7 blind 재판정에서 hybrid 가 RMSE 3승 1무로 기본 채택됨(D013 준수).
`run_window_pipeline.py` 는 이 인자를 안 넘기므로 hybrid 로 동작한다.
실행 산출물로 확인: `kr_fit_by_lmin.json → input_summary.likelihood_mode = "hybrid"`,
`lmin_fit_values = [0.5]` (hybrid 기본; window_mc 였다면 [0.1,0.2,0.3,0.5,0.75]).
→ (1)·(2) 에 "window MC" 라고 적었던 라벨은 오기이며 이 커밋에서 정정했다.

# (4) kr 산출물에 실제 likelihood_mode 기록

## 문제
`kr_summary_by_set.csv` 의 `notes` 열이 어떤 우도 방식으로 돌렸든 항상
`"v4.1 polygon window MC uses tunnel polygon clipping; ..."` 만 출력했다.
이 문자열은 **창(window) 기하에 대한 경고**이지 우도 방식을 뜻하지 않는데,
`likelihood_mode` 가 요약 CSV 어디에도 없어서 window_mc 로 오해하기 쉬웠다.
(이번 세션에서 실제로 그렇게 오독했다 — (3) 참조.)

## 변경 (`dfn_analysis/radius_powerlaw_likelihood.py`)
- `determine_status(...)` 에 `likelihood_mode: str = ""` 인자 추가.
  경고 리스트 맨 앞에 `likelihood_mode=<모드>` 를 넣는다.
- `fit_set_lmin` 의 호출부(line 1352)가 실제 `likelihood_mode` 를 전달.

# (5) handoffv3 시험 — 파이프라인 프로세스 통합 (in-process 오케스트레이션)

## 만든 것
`handoffv3/` 신설. **코드만 복사**(2.7 MB) — `dfn_analysis/`, `scripts/`,
`dfn generator v1/`, README·requirements 등. `example_io`(1.9 G)·`demodata`(401 M)·
`demo_output`(307 M)는 복사하지 않고 v2 것을 참조한다(`DFN_DFM_DIR` 환경변수로 override).

**`dfn_analysis/`·`scripts/` 는 v2 와 바이트 동일**하다(`diff -r` 확인).
바뀐 파일은 `scripts/analysis_260903/run_window_pipeline.py` 하나뿐이다.

## 변경 내용
v2 는 단계마다 `subprocess.run([sys.executable, "-m", ...])` 로 새 프로세스를 띄웠다.
v3 는 6개 모듈을 **맨 위에서 한 번 import** 하고 각 단계에서 `main()` 을 직접 호출한다.
모듈이 `argparse` 로 `sys.argv` 를 읽으므로 호출 직전에 `sys.argv` 를 교체하고
`SystemExit` 을 흡수한다. **모듈은 손대지 않았다.**
6개 모듈 전부 `main()` 을 갖고 있어 가능했다(`estimate_p32_mc_calibrated` 는 셔틀로 재수출).

## 결과 — 산출물 동일
`win_cmp`(면 01~04) 를 v2·v3 에서 각각 생성해 14개 파일 비교:

| 대상 | 결과 |
|---|---|
| CSV 7종 + HDF5 2종 + txt 1종 | **바이트 동일** |
| `conversion_diagnostics.json`, `kr/kr_fit_by_lmin.json` | 경로 문자열만 상이 (handoffv2/ vs handoffv3/). 경로·NaN 정규화 후 완전 일치 |

전역 상태 누수·난수 오염은 관측되지 않았다.

# (6) 순차 갱신 시험 (브랜치 feat/sequential-update-v3, handoffv3)

## 목적
면별 우도를 누적하는 순차 베이즈 갱신이 (a) 현행 배치 재역산과 같은 답을 주는지,
(b) 창 간 kr 변동을 줄이는지 시험. EnKF 도입 전 선행 단계.

## 방법
`handoffv3/scripts/seq_update/seq_update_experiment.py` (신규).
면 01~07 에 대해 단일면 7개 + 누적창 7개, 총 14회 `convert → estimate_kr`.
순차 사후 = Σ_f logL_f(kr) (균등 사전), 배치 = 누적창 직접 적합. 전처리+적합 24초.

## 결과 — 결론 불가. 전제가 깨졌다.

### 발견 1: 전역 set 번호가 창 구성에 따라 바뀐다
`convert_dfm_export_to_trace_dataset.py:183-187`
```python
# 절리선 수 내림차순으로 전역 set 번호 부여
order = sorted(counts, key=lambda k: -counts[k])
relabel = {k: i + 1 for i, k in enumerate(order)}
```
면을 추가하면 절리선 수 순위가 바뀌어 번호가 교환된다. 게다가 군집화(`fcluster`,
절단 30°)가 **포함된 면만으로** 다시 돌아 군집 구성 자체도 달라진다.

누적창 1~7 을 cum_7 기준으로 대조:
| 창 | 매핑 | 비고 |
|---|---|---|
| cum_1~4 | {1:2, 2:1, 3:3, ...} | **set 1↔2 교환** |
| cum_5 | {1:2, 2:1, 4:1, 5:5} | 일대일 아님 |
| cum_6 | {1:2, 2:1, 3:3, 4:1, 5:4, 6:5} | 두 set 이 하나로 병합 |

→ "set 1 의 kr" 을 창 간에 더하거나 비교하는 것이 성립하지 않는다.
순차 누적 실험은 이 때문에 **무효**다(서로 다른 물리적 군집의 우도를 더했다).

### 발견 2: 실제 전달·발표 자료에도 같은 문제가 있다
`handoffv2/demo_output` 의 실제 창들 (기준 = win_f01-07_l05):
| 창 | 매핑 | 단사 |
|---|---|---|
| win_f01-04_l05 | {1:2, 2:1, 3:3, 4:4, 5:5} | O — **1↔2 교환** |
| win_f01-06_l05 | {1:2, 2:1, 3:3, 4:1, 5:4, 6:5} | X — 병합 |

kr 비교에 미치는 영향:
```
[현재 발표자료가 읽히는 방식]      [set 대응 정정 후]
set  f01-04 f01-06 f01-07          set  f01-04 f01-06 f01-07
 1    3.65   4.00   3.90            1    3.80   3.80   3.90
 2    3.80   3.80   3.85            2    3.65   4.00   3.85
 3    3.45   3.65   3.65            3    3.45   3.65   3.65
```
set 1 의 창 간 변동이 0.35 → 0.10 으로 줄어든다.
**즉 "창 간 kr 불안정성" 의 상당 부분이 라벨링 artifact 일 수 있다.**

### 발견 3: 우도의 bin 경계가 데이터 의존
`make_length_edges` 의 상한 = 관측 최대 길이. 실행별 상한이 2.69~9.55 m 로 제각각.
다항우도는 counts 에 가법적이지만 bin 정의가 다르면 더할 수 없다.
방향 풀(`empirical_trace_directions_yz`)도 같은 문제. 상한 고정 옵션은 없다.

## 참고: 무효 조건부 수치
set 번호 문제를 무시하고 계산한 값(신뢰할 수 없음):
창을 하나 넓힐 때 kr 변동 평균 — set1 0.225→0.100(−56 %), set2 0.142→0.083(−41 %),
set3 0.175→0.142(−19 %). 순차가 더 안정적으로 보이나, 누적은 새 관측이 1/n 비중만
갖는 **기계적 평활**이라 정확도 개선의 증거가 아니다. set 2 에서 순차가 배치보다
일관되게 +0.25~0.50 높은 계통 편차도 있었다.

## 다음 단계 (미착수)
1. **set 번호 안정화가 선결 과제.** 번호를 절리선 수 순위가 아니라 불변 키

2. bin 상한 고정 옵션(`--length-bin-upper`) 추가 → 면별 우도의 엄밀한 가법성 확보.
3. 그 다음에야 순차 갱신 재시험이 의미 있다.
4. **면 간 관측 독립 가정**은 순차·배치 모두 공유한다. 큰 원판은 여러 면에 절리선을

## 시험 조건
전체 면(01~07)으로 1회 변환해 기준 set 정의·터널축을 만들고, 단일면 7개와
누적창 7개를 **모두 그 기준으로** 변환·적합. bin 상한 12.0 m 공통.

## 결과 — 순차 ≡ 배치
| set | 순차 kr − 배치 kr |
|---|---|
| 1 | 전 구간 0.00 |
| 2 | 0.00 (n=5,7 에서 ±0.05) |
| 3 | 0.00 (n=7 에서 −0.05) |

kr 격자 간격이 0.05 이므로 잔차는 격자 한 칸, 즉 수치 오차 수준이다.
**다항우도 loglik = Σ counts·log(prob) 가 counts 에 가법적이므로, 관측 모형이
공통이면 Σ_f logL_f(kr) = logL_batch(kr) 이 성립한다.** 순차 갱신은 현행
재역산과 수학적으로 같은 답이며, 정확도 면에서 얻을 것이 없다.

| set | 고정 전 | 고정 후 |
|---|---|---|
| 1 | 0.225 | **0.117** |
| 2 | 0.142 | **0.117** |
| 3 | 0.175 | **0.117** |

set 번호 교환·bin 경계·터널축이 창마다 달라진 탓이 절반 이상이었다.
고정 후에는 순차(0.108~0.117)와 배치(0.117)의 안정성 차이도 0~7 % 로 사라진다.
(고정 전에는 순차가 19~56 % 더 안정해 보였으나 이는 무효 조건에서의 수치였다.)

## EnKF 판단에 대한 함의
파라미터 수준에서는 갱신이 이미 정확하고 추정도 안정적이므로 EnKF/ES-MDA 가
보탤 것이 없다. 앙상블 자료동화가 유효해지는 지점은 **관측연산자가 비싼 경우**
— 블록·쐐기 발생 관측, 여굴 형상, 계측 변위 등(실현당 10초 이상, MCMC 불가) — 이다.

## 남은 한계

- 단일면 적합은 64 bin × 3 등급 = 192 셀에 트레이스 120~330 개로 희소하다.
  개별 면 우도의 소표본 편향은 별도로 확인하지 않았다.

# (8) 면 간 관측 상관이 kr 에 주는 편향 측정

## 문제
우도는 `loglik = Σ_trace log p(trace|kr)` 로 절리선을 전부 독립 표본으로 본다.
전방 모형(`simulate_window_from_true_chords`)은 **원판 1개 × 창 1개 → 가시길이 1개** 를
모사한다. 그런데 관측은 7개 면을 풀링하므로 큰 원판은 여러 면에 절리선을 남긴다.
스크립트: `handoffv3/scripts/seq_update/crossface_dup.py`

## 중복 구조 (7면, 복원 association 기준)
절리선 4,630개 → 복원 원판(군집) 3,061개

| 관통 면 수 | 원판 수 | 그 원판들의 절리선 수 |
|---|---|---|
| 1 | 2,716 | 3,192 |
| 2 | 291 | 1,064 |
| 3 | 49 | 333 |
| 4 | 5 | 41 |

다면 관통 원판 345개(11.3 %)가 절리선 1,438개(**31.1 %**)를 차지한다.

## 기전 — 위성 절리선은 '짧은 쪽'에 몰린다
| 집단 | n | 중앙 | 평균 | p90 |
|---|---|---|---|---|
| 단일면 원판의 절리선 | 3,192 | 0.21 m | 0.40 | 0.90 |
| 다면 원판의 **최장** 절리선 | 345 | 0.68 m | 0.90 | 1.84 |
| 다면 원판의 **위성**(나머지) | 1,093 | 0.19 m | 0.26 | 0.52 |

다면 원판은 중심에 가까운 면에서 긴 현, 먼 면에서 짧은 현을 남긴다
(현 반길이 = √(r²−t²), t = Δx/sinφ). 위성 절리선 1,093개(**전체의 24 %**)가 짧은
길이 구간을 채운다. 단일창 모형은 이들을 예측하지 못하므로, 적합은 크기분포를
더 가파르게 만들어 보정한다 → **kr 과대추정**.

## kr 민감도
| 데이터셋 | 절리선 | set1 | set2 | set3 |
|---|---|---|---|---|
| full (현행) | 4,630 | 3.90 | 3.85 | 3.70 |
| dedup_face (같은 면 조각 제거) | 3,465 | 3.80 | 3.60 | 3.60 |
| dedup_cluster_rand (군집당 무작위 1) | 3,061 | 3.55 | 3.40 | 3.50 |
| dedup_cluster_long (군집당 최장 1) | 3,061 | 3.70 | 3.50 | 3.55 |

**kr 이 0.20~0.45 움직인다.** (7)에서 잰 창 간 변동 0.117 보다 크다.
방향은 전부 감소 — 즉 현행 추정은 **큰 균열을 과소평가하는 쪽**이며 비안전측이다.

## 해석 — dedup 은 정답이 아니다
- `dedup_face` (같은 면 조각 병합)는 순수 매핑 artifact 제거라 정당하다. kr −0.10~−0.25.
- `dedup_cluster` (면 간 중복 제거)는 **과보정**이다. 7개 면을 7개 창 표본으로 보는 것이
  맞다면, 다면 원판이 여러 면에 현을 남기는 것은 모형이 **예측해야 할 현상**이지
  버릴 관측이 아니다. 현재 모형이 단일창이라 예측하지 못할 뿐이다.
- 따라서 참값은 full 과 dedup_cluster 사이에 있고, 올바른 해법은
  **전방 모형을 다면(평행 창 N개)으로 확장**하는 것이다.

## 유효표본
독립 표본 수는 절리선 4,630 이 아니라 원판 3,061 에 가깝다.
우도 기반 신뢰구간은 √(4630/3061) ≈ **1.23 배 과소**로 나온다.
(측정된 Δ≤2 구간 폭은 dedup 후에도 거의 변하지 않았다 — 계통 오설정이 지배하는
것으로 보이나 별도 확인은 하지 않았다.)
